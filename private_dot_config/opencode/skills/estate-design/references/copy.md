# Copy is design content

Words exist to make the thing easier to understand and use. Template-feeling
copy destroys a design as fast as template-feeling layout.

## Voice rules

1. **User's perspective, not the system's**: "notifications", not "webhook
   configuration"; "your teams", not "workspace entities".
2. **Active voice; CTAs say what happens**: "Save changes", not "Submit";
   "Create project", not "Continue".
3. **One name per action through the whole flow**: the button says
   "Publish", the toast says "Published", the docs say "publishing".
4. **Plain before clever**: specific and legible beats witty and opaque.
5. **Sentence case** for labels, buttons, and headings unless the brand
   explicitly says otherwise.
6. **Errors direct, never apologetic**: state what happened, why, and the
   way out. "Upload failed — the file is 30 MB; the limit is 25. Compress
   and retry." Not "Oops! Something went wrong."
7. **Empty states invite action**: say what will appear here and offer the
   one action that creates it.
8. **No filler**: no "simply", "easily", "just", "powerful", "seamless" —
   the words that carry no information.

## Real content over placeholder

Design with the brief's real content wherever it exists. If inventing
placeholder copy, invent *specific* copy (a real-sounding product name, a
plausible price, a concrete outcome) — generic placeholder ("Your content
here", "Feature one") reads as unfinished and biases every layout decision.

## Numbers and claims

Never invent metrics, testimonials, customer counts, or logos. If the brief
supplies them, use them exactly. If a section needs proof and none exists,
use structure that works without proof (a concrete description, a real
screenshot, a named method) rather than fabrication.

## Microcopy inventory (every screen)

Every screen needs: page title (what this is), primary action label, empty
state, error state for each data source, loading treatment, and confirmation
for destructive actions. Missing microcopy is missing design.
